# Capability matrix and verification evidence

This matrix summarizes the implemented capabilities of AgentShelf, where they are implemented, the verified environments, references to public verification evidence, known operational limits, and acceptance criteria for final release rehearsals.

## Evidence levels

Every claim in the docs uses one of these evidence levels. A level is only valid with a date, a commit or a link. PayPal Sandbox evidence (an order or event at PayPal) and hosted-service evidence (a check of the deployed service) are recorded separately, because one does not imply the other.

| Level | Meaning |
| --- | --- |
| `implemented` | Code exists and automated tests pass, using stand-ins such as the in-process fake PayPal provider (`test/payments.ts`) |
| `locally tested` | Run on a developer machine against our own PostgreSQL and a local server |
| `live/read-only verified` | A dated, non-mutating check on the hosted service (`https://agentshelf-e5bk.onrender.com`), such as health, tool listing or search. Name the commit. It says nothing about PayPal unless a PayPal Sandbox record is cited |
| `live/mutating rehearsal verified` | A dated hosted action that changes state, such as registration, upload, booking or payment. Name the commit and the action; cite PayPal Sandbox evidence separately |
| `external client verified` | A real external client, named with version and date (for example Claude Code 2.1.282), called the hosted endpoint. It is never generalised to another client such as claude.ai or ChatGPT |
| `not tested` | No run exists, or only a failed or unconfirmed one |

Vendor documentation is not evidence at any level.

## Explicit non-goals & out-of-scope boundaries

1. **No Live Money or Real Banking:** AgentShelf operates exclusively against PayPal Sandbox. No live PayPal credentials or production merchant onboarding are supported.
2. **Human Payment Confirmation Always Required:** Autonomous agents never charge customer payment methods directly. Agents only generate PayPal approval URLs; human buyers must log in to PayPal Sandbox to authorize the charge.
3. **No Unbounded General Client Promises:**
   - **Seller MCP:** `external client verified` with Claude Code CLI only (Bearer token authentication). Third-party web agents without custom HTTP authorization headers (e.g., standard ChatGPT web MCP connectors) cannot pass seller bearer grants.
   - **Buyer MCP:** Standard Streamable HTTP `/mcp` without sign-in, protected by strict schema parsing and allowed origin filtering (`claude.ai`, `chatgpt.com`, or configured allowed origins).
4. **No Automated Unlimited Inventory:** Products imported from CSV or photo never default to infinite stock. Sellers must explicitly configure tracked quantity or choose untracked mode before checkout is allowed.
